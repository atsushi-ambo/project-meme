# 検証結果（2026-10-28、Muse の Linux VM で実行）

デモデータ（正解ルール：`y = 1.2 + 0.9*sin(2*pi*(hour-6)/24) + 3.0/(1+hours_since_food) + 0.3*is_weekend + ノイズ`、60日×24時間=1,440行）に対する実行結果。

## niterations=60（約44秒）

- R^2 = 0.781
- 複雑度6の式で既に `2.02 - cos(hour * 0.2605)` を発見。正解の角周波数 2π/24 = 0.2618 に対して 0.2605 とほぼ一致し、1日周期そのものを捉えた
- 自動選択された式（複雑度13）：`sin(food_this_hour + hours_since_food*(-0.122)) + (2.453 - cos(hour * -0.260))`
  - 食事からの経過時間に対する減衰も sin の合成で近似的に再現

## niterations=200（約85秒）

- R^2 = 0.847
- 選択式：`(sin(hours_since_food*(-0.108) + sin(hours_since_food*(-0.228))) + 1.769)*2.091 - cos(hour*0.26168)`
  - 角周波数 0.26168 は正解 0.26180 と小数第3位まで一致
  - ただし `3.0/(1+hours_since_food)` の有理式そのものは復元されず、sin の入れ子による近似になった。is_weekend の項も独立には分離されなかった

## 読み方

- 「1日周期の存在と周波数」「食事からの時間で減衰する」という構造は、ノイズ入りのデータからでも正しく拾える
- 一方で、正解の関数形そのものを完全復元できるわけではない。出てきた式はあくまで仮説候補として扱い、project-meme 側で根拠を積んで検証する前提
- 反復回数を増やすと当てはまり（R^2）は上がるが、式は複雑化する。解釈可能性とのバランスは複雑度で選ぶ

生ログは `demo_result.txt`（60回）と `demo_result_200.txt`（200回）にあります。

## 環境メモ

- 検証は Muse の VM（Linux）で実施。この VM 固有の事情として、Julia の展開先に 512MB の tmpfs（/tmp）が使われて容量不足になったため `TMPDIR` をワークスペース配下に向け、展開された Julia バイナリの実行権限も手で直した。Mac 上の通常インストールでは不要なはずの対処
- 君の Mac で使う場合は README の手順どおりでよい

## 実データ疎通チェック（2026-10-28）

Mac 上のアプリを Muse が操作して全データ出力（ZIP 約2.1GB）を実行し、records.json（24KB）を取得して取り込みまで確認した。パイプラインは実データで疎通済み。

ただし、式発見に足るデータ量ではなかったため、実データでの PySR 実行は見送った：

- 観察：9件（2026-10-04〜10-27）。1時間単位に集計すると553行中545行がゼロで、観察のある時間帯が8つだけ
- 健康記録：サンプル行1件（体重）のみ。サンプルを除くと0件で、食事記録が無いため `hours_since_food` は全行24.0の定数になる。嘔吐の記録もゼロ
- 辞書には仮説5件・根拠15件が登録済みだった

再挑戦の目安：観察が100件を超えて時間帯にばらつきが出ること、食事・水分・トイレの健康記録が入り始めること。その状態になれば、このスクリプトをそのまま実データに当てられる。
