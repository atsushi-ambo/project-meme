# めめのノート：初版の設計

## 目的と対象

飼い主が日常の声・行動・体調を少ない操作で記録し、過去の似た場面と比べられるようにする。iPhoneのChromeを主対象とし、iPadとMacBookのブラウザでも同じアカウントで利用する。自宅のMacBookでPythonサーバーを動かし、同じWi-FiのChromeから利用する。インターネット公開は初版の条件にしない。

初版で約束するのは記録・振り返り・共有用の出力。猫語の翻訳、診断、記録だけでAIが自動学習することは約束しない。

## 決定済みの条件と仮定

- めめ1匹、飼い主1アカウントから始める。
- 写真は手元にあり、鳴き声の動画はこれから集める。
- 写真や動画を添付でき、添付なしでも記録できる。
- メディアの標準保存期間は60日。日記の文章・時刻・タグは期限後も保存する。
- 開発にはMacBookのCodexを利用できる。
- 仮の名称は「めめのノート」。年齢、既往歴、食事、写真は後から登録する。

## 初版の画面

### ホーム

めめの写真、今日の記録、直近の体調メモを表示。「声・行動を記録」「体調を記録」を大きく配置する。日付ごとの未入力を異常やゼロと扱わない。

### 声・行動を記録

iPhoneのカメラで撮った写真・動画を後から取り込み、状況タグを保存する。初期タグは「食事前」「ドアの前」「遊び」「帰宅」「触れている」「その他」。入力は時刻、状況、こちらがしたこと、めめの反応、任意メモ。撮影日時と記録日時を区別し、撮影日時が不明なら確認できるようにする。

初版はブラウザ内の撮影・録音を実装しない。ファイル選択、内容確認、状況入力、保存の順とする。撮影日時を取得できない場合はユーザーが指定する。MacBookへの保存完了を確認してからiPhoneの元動画を整理する。

### 体調日記

「吐いた」「食事」「水」「トイレ」「体重」「元気」「その他」を記録する。吐いた記録は日時、回数、内容、食事との間隔、食欲、元気、写真、任意メモ。分からない項目は空欄で保存する。体重は単位つきで入力する。

以前の嘔吐については詳細が未提供。事実を作らず、後から過去の日付で入力できるようにする。

履歴を日付で絞り、獣医に見せるための印刷用ページとCSVを出力する。印刷用ページはブラウザの「PDFに保存」を利用できる。診断や「健康です」という判定を出さない。繰り返す嘔吐、ぐったりしている、血が混じる、水も保てない等の記録では、獣医への相談を促す短い固定案内を表示する。案内の最終文言は公開前に確認する。

### めめ辞書

「ごはんの要求かも」などの飼い主の仮説と、その根拠になる記録を結びつける。「未確認」「反応を記録済み」で状態を示す。反応が一致しても意味が確定したとは表示しない。初版の候補は飼い主が選び、AI翻訳のように見せない。

こちらから伝える言葉・合図も保存する。例：「遊ぼう」と声をかけておもちゃを出した、めめが近づいた。猫語の音声生成は対象外。

### 設定と保存管理

めめのプロフィール、保存容量、期限が近いメディア、保存期間、データ出力、個別削除、全削除を扱う。代表クリップは明示的な「残す」指定で期限対象外にできる。残すクリップも容量上限に含める。

## 60日の保存と容量

60日は標準の保存期間であり、容量が無制限という意味ではない。費用と契約上限を決めてから、1ファイル・合計容量・動画長の上限を設定する。上限超過時に古いデータを黙って消さず、新規添付を止めて整理を案内する。文章の記録は続けられる。

1. 取り込む前に、可能な場合は長さとサイズを表示する。
2. 対応形式なら圧縮版を生成し、元データと分けて扱う。元データをMacBookに保存する場合も標準60日で削除する。
3. アップロードとMacBook側の受領を確認するまで「保存済み」にしない。
4. 初版では圧縮版・音声・サムネイルを含むメディアも60日の期限対象にする。「残す」指定だけ例外とする。
5. 保存開始から53日で画面内に期限案内を出す。60日で閲覧対象から外し、削除ジョブでオブジェクトを削除する。失敗は再試行し、削除完了を記録する。
6. 日記には「添付は保存期限により削除済み」と残す。仮説の根拠が消えた場合も明示する。

ブラウザはiPhoneの写真ライブラリにある元動画を自動削除できない。アップロード確認後、ユーザーが写真アプリで削除する必要がある。「最近削除した項目」やiCloud写真の同期も考慮した案内を用意する。アプリに保存しただけではiPhoneの容量は減らない。

ブラウザ内の圧縮はiOSのメモリ・電池・対応形式に制約がある。初版はカメラで撮った既存ファイルの取り込みを優先し、動画変換はサーバー側を第一候補にする。写真のHEIC、動画のHEVC・向き、Chromeでの取り込み・再生対応は実機で確認する。音声と静止画だけでは失われるしぐさがあるため、それだけで翻訳できるとは扱わない。

バックアップの保持期間と削除反映はサービス選定後に明記する。「60日で全コピーが消える」と、確認なしに表示しない。

## 技術構成の候補

- Python + FastAPIをサーバーに採用。画面はJinja2テンプレートとHTML/CSS、録音・アップロードに必要な少量のJavaScriptで実装する。スマートフォン優先のUI、PWA manifestを用意する。
- SQLiteはRDB。記録と添付の関連を保存する。動画本体はMacBookのGit管理外のデータフォルダに置き、DBには相対パス等を保存する。Pythonの学習を目的に、処理の流れが追える構成にする。
- 初版はMacBook上のSQLiteとメディアフォルダを利用する。LANアクセスにもログインを設ける。将来クラウドへ移す場合はPostgreSQLや非公開オブジェクト保存を検討する。
- 動画変換と削除処理はサーバーのジョブに分離する。実行環境と費用の確認後に選定する。
- AI接続は初版の必須条件にしない。追加時は対応する音声・画像モデル、料金、データ利用条件を確認する。
- オフラインで画面の表示は可能にするが、初版はオンライン保存を基本にする。保存失敗時は入力を保持して再試行できるようにし、未送信と保存済みを区別する。

録音とPWAにはHTTPSが必要。iPhoneのChromeもバックグラウンドでアップロードが止まる可能性があるため、完了までは画面を開いておく案内を出す。端末内ストレージは消える可能性があり、永続保存の唯一の場所にしない。

## データ構造

- cats: id, owner_id, name, profile_photo_id, birthday（任意）, notes
- entries: id, cat_id, kind, occurred_at, created_at, timezone, situation_tags, note
- behavior_details: entry_id, hypothesis, owner_action, cat_response
- health_details: entry_id, event_type, count, weight_value, weight_unit, appetite, energy, details
- media: id, entry_id, owner_id, object_key, mime_type, bytes, duration, status, retention_started_at, expires_at, keep, deleted_at
- dictionary_items: id, cat_id, title, cue, hypothesis, status
- dictionary_evidence: dictionary_item_id, entry_id

詳細項目は型と入力規則を実装時に定義する。時刻はUTCで保存し、表示は利用者のタイムゾーンに合わせる。

## プライバシーと安全な保存

写真・音声に家族の顔や声が入る前提で、ログイン必須、メディアは静的公開フォルダ外に保存し、認証済みルートからのみ閲覧できるようにする。LANでもアクセス制御、CSRF対策、アップロードのサイズ・形式・パス検証を行う。将来クラウドに移す場合、非公開保存と短期間の署名URLを使う。認証情報をブラウザやリポジトリに埋め込まない。ログにメディア内容や署名URLを残さない。

全データ出力と削除を提供する。AI送信を追加するときは送信対象を説明し、利用者が有効化してから送る。位置情報など不要なメタデータは公開・解析用の派生画像から除去する。

## 開発順序と完了条件

### 1. ローカル試作

サンプルデータで全画面を操作できる。声・行動と体調を添付なしで入力できる。辞書に根拠を追加できる。保存状態を正直に表示する。仮データは仮データと分かる表示にする。

### 2. 保存と同期

ログイン、SQLite、MacBook上のメディアフォルダを接続。iPhoneからMacBookに保存した記録をMacBookのChromeでも確認できる。他のユーザーの記録・添付にアクセスできないことを検証する。

### 3. メディアと保存期間

実機のカメラ動画の取り込み・再生、通信切断、容量上限、期限削除と「残す」を確認する。時刻を制御した検証で60日を待たずに期限処理を確認する。アップロード失敗や削除失敗を成功と表示しない。

### 4. 日常利用

印刷・CSV、iPad/MacのChromeで表示を確認。ホーム画面への追加は後続で対応。使いながら項目とタグを調整する。

### 5. 後続のAI実験

記録が集まったら、状況だけの推測と、声・画像を加えた推測を比較する。飼い主の推測を正解扱いせず、その後の行動も評価する。同じ動画から切り出したデータを学習と評価に分けない。数値の確率を出すなら校正の検証が必要であり、未検証の「90%」などは表示しない。

## 実装前に選ぶこと

MacBookの保存容量上限、ログイン方式、バックアップ先と保持期間。クラウド移行時は別途、保存サービス・月額上限・保存地域を選ぶ。

## 開発環境

このbase environmentではPython 3.12.14を確認済み。ここでコードとローカル検証を進め、同じGitリポジトリをMacBookで開いて継続する構成を推奨する。リポジトリの初期化・リモート作成は未実施。MacBookではChromeとiPhone実機で録音・アップロード・表示を確認する。iPhoneからMacBookのlocalhostにはアクセスできないため、実機確認にはHTTPSのプレビューURLまたは適切に設定した開発用接続を用意する。開発環境を60日保存の本番サーバーとして使わない。公開時の常時稼働・永続ストレージ・期限ジョブは別途用意する。

## 自宅運用の条件

MacBookのサーバーが起動中で、端末が同じLANにいるときに利用する。スリープ中はアクセスできない。ルーターの外部ポート公開は不要。SQLiteとメディアはセットでバックアップし、バックアップの保持期間は別途決める。期限処理は起動時と起動中の定期ジョブで実施し、停止中の未処理分は再起動後に処理する。60日ちょうどに停止中のMacBookから物理削除されるとは約束しない。直接録音を実装しない初版はLAN内HTTPでもファイル取り込みが可能。HTTPSとPWAは後続で整える。
